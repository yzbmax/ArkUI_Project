## 一、项目概览

这是一个**鸿蒙原生音乐 App**（黑马云音乐），来自黑马程序员 HarmonyOS 开发课程第 9 章的教学项目。项目使用 ArkTS 语言，基于 HarmonyOS API 12（5.0.0 版本）的 Stage 模型开发。

主要功能包括：

- **启动广告页**：5 秒倒计时自动跳转或手动跳过
- **底部四 Tab 导航**：推荐、发现、动态、我的
- **音乐播放器**：完整的播放/暂停、上下曲、进度条、播放模式切换（顺序/单曲循环/随机）
- **播放列表管理**：添加歌曲、删除歌曲（左滑删除）
- **媒体会话**：锁屏和控制中心显示歌曲信息与播放控制
- **网络数据加载**：通过 HTTP 请求获取首页推荐数据、歌曲列表、动态内容等

## 四、页面与组件功能一览

### 4.1 三页面总览

| 页面文件 | 功能描述 | 关键技术点 |
|----------|---------|-----------|
| **Start.ets** | 启动广告页，展示广告图，5 秒倒计时自动跳转到主页，也可点击"跳过"按钮手动跳转 | `setTimeout` 定时器、`router.replaceUrl` 路由替换、`@StorageProp` 安全区域适配 |
| **Index.ets** | 主页框架，底部 4 个 Tab（推荐/发现/动态/我的），点击切换对应视图，自定义 TabBar 样式 | `Tabs` + `TabContent`、`@Builder` 自定义 TabBar、`ForEach` 循环渲染、条件渲染 `if/else`、`@State` 激活态管理 |
| **Play.ets** | 🔥 音乐播放器页，是整个项目最核心、代码量最大的页面（~350 行） | `Animator` 动画（封面旋转）、`Slider` 进度条、`List` 播放列表、`swipeAction` 滑动删除、`@Watch` 监听播放状态、面板动画 |

### 4.2 四个 Tab 视图

| 视图组件 | 功能描述 | 关键技术点 |
|----------|---------|-----------|
| **Recommend.ets** | "推荐"Tab——搜索栏 → Swiper 轮播图 → 每日推荐（横向滚动） → 推荐歌单（横向滚动） | `Swiper` 自动轮播、`Scroll` 横向滚动、`@Builder` 多区块复用、`Stack` 叠加布局、`aboutToAppear` 异步加载数据 |
| **Find.ets** | "发现"Tab——展示"猜你喜欢"歌曲列表，点击歌曲跳转到播放页并开始播放 | `List` + `ListItem` 列表渲染、路由跳转 `router.pushUrl`、`AVPlayerManager.singPlay()` 触发播放 |
| **Moment.ets** | "动态"Tab——互动广场，展示用户动态，每条动态内嵌歌曲卡片，含分享/评论/点赞数 | 复杂嵌套布局、`Badge` 组件、歌曲卡片内嵌设计 |
| **Mine.ets** | "我的"Tab——Logo 头像、个人信息（昵称/VIP/年龄/星座/城市）、关注粉丝数据、`GridRow` 瀑布流封面，包含子组件 `SongCard` | `GridRow`/`GridCol` 响应式网格、子组件拆分 `SongCard`、数据随机排序、`scale` 缩放效果 |

  playList: SongItemType[] = [];     // 播放列表
}

## 五、Preview 报错分析与解决方案

### 5.1 报错信息

```
Current project in this API version does not support preview
```

### 5.2 原因分析

| 层面 | 详细说明 |
|------|---------|
| **API 版本兼容** | 项目使用 `compatibleSdkVersion: "5.0.0(12)"`（API 12），你的 DevEco Studio 版本可能不完全支持 API 12 的 Previewer 功能 |
| **系统 API 依赖** | 代码大量使用了 Previewer **不支持**的系统级 API：<br>• `@kit.MediaKit` — AVPlayer 音频播放<br>• `@kit.AVSessionKit` — 媒体会话<br>• `@kit.NetworkKit` — HTTP 网络请求<br>• `@kit.AbilityKit` — Router 路由跳转 |
| **Runtime 上下文** | `Start.ets` 在 struct 级别直接调用了 `this.getUIContext().getRouter()`，Previewer 中没有真实的 UIContext（运行时上下文） |

### 5.3 解决方案（按推荐顺序）

#### ✅ 方案一（强烈推荐）：使用模拟器运行

```
DevEco Studio → 菜单栏 Tools → Device Manager
→ 创建 HarmonyOS 模拟器（选择 API 12 镜像）
→ 点击顶部工具栏的 Run 按钮 → 选择模拟器运行
```

模拟器拥有完整的系统能力，可以运行所有 `@kit.*` API。

#### ✅ 方案二：真机调试

- 使用 USB 数据线连接 HarmonyOS 手机或平板
- 在设备上开启「开发者模式」和「USB 调试」
- 在 DevEco Studio 的设备列表中选择真机
- 点击 Run 按钮运行

#### ⚠️ 方案三（仅临时看 UI）：降低 API 版本 + 修改代码

如果只是临时快速查看 UI 布局效果，可以修改以下文件（**完成后记得改回来**）：

**1. 修改 `build-profile.json5`**：
```json5
// 第 9 行和第 16 行，将 5.0.0(12) 临时改为：
"compatibleSdkVersion": "4.1.0(11)",
"targetSdkVersion": "4.1.0(11)"
```

**2. 修改 `Start.ets`**：
```typescript
// 将 struct 级别的这行代码
router = this.getUIContext().getRouter();
// 移到 aboutToAppear() 方法内部
```

> ⚠️ 注意：这种方法只能预览 UI 布局，无法调试音频播放、网络请求等功能。最终开发和调试还是需要使用模拟器。

## 七、核心模块深度解读

### 7.1 AVPlayerManager（音频播放管理器）

**文件**：`entry/src/main/ets/utils/AVPlayerManager.ets`（~150 行）

这是一个**静态类**，采用单例模式管理全局唯一的 AVPlayer 实例。

#### 核心属性

```typescript
static player: media.AVPlayer;            // AVPlayer 实例（全局唯一）
static currentSong: PlayState;            // 当前播放状态（单例）
```

#### 核心方法

| 方法 | 功能 | 关键逻辑 |
|------|------|---------|
| `init()` | 创建 AVPlayer 实例并注册事件监听 | 只创建一次（判空）；注册 3 个事件：`stateChange`、`durationUpdate`、`timeUpdate` |
| `singPlay(song)` | 播放指定歌曲，自动加入播放列表 | ① 已在列表中且是当前歌曲 → 继续播放<br>② 已在列表中但不是当前歌 → 切换索引<br>③ 不在列表中 → unshift 到列表头 |
| `changePlay()` | 切换当前播放的歌曲 | `player.reset()` → 更新 `currentSong` 属性 → 设置新 URL |
| `pause()` | 暂停播放 | `player.pause()` + 更新 `isPlay` + 通知 AppStorage |
| `prevPlay()` | 上一首（支持随机模式） | 随机模式 → 随机索引；顺序模式 → index-1（循环到末尾） |
| `nextPlay(isRepeat?)` | 下一首（支持单曲循环） | 单曲循环 → 不换索引；随机 → 随机；顺序 → index+1（循环到开头） |
| `remove(index)` | 删除播放列表中的歌曲 | 智能处理：删除当前歌/前面歌/后面歌的不同情况 |
| `getRandomIndex()` | 获取随机索引（排除当前） | do-while 循环确保不等于当前索引 |

### 8.2 搭建 Mock 服务的建议

**方案二：使用 Mockoon**

- 下载 Mockoon（https://mockoon.com/）
