## 瀑布流改用官方 WaterFlow + LazyForEach（成熟开源方案）
- 用户要求参考成熟开源项目实现无限瀑布流。调研结论（HarmonyOS 官方 + 小红书/资讯类开源实践）：
  - 用 `WaterFlow` 容器（最短列优先真瀑布流）而非 `Scroll`+手动两列 `Row/Column`（后者错落是假的且 `onReachEnd` 不稳）。
  - `LazyForEach` + `IDataSource` 数据源：只渲染可视区域 = 真正图片懒加载 + 高性能。
  - 提前预加载：不用 `onReachEnd`（到底有明显停顿），用 `WaterFlow.onScrollIndex` 在还剩若干条未遍历时（本项目 `PREFETCH_THRESHOLD=5`）提前 `pushPage` 下一页，丝滑无限滚动。也可在 `FlowItem.onAppear` 判断即将触底时追加。
  - 数据追加驱动刷新：`IDataSource` 的 `pushPage` + `onDataAdd`/`onDataReloaded` 通知。
- 实施：
  - 新增 `components/WaterfallDataSource.ets`：`WaterfallDataSource` 类（不 import IDataSource，用本地 listener 接口做结构匹配，规避 SDK 26 未导出问题），`pushPage`/`reset`/`totalCount`/`getData`/register/unregister。
  - `views/Recommend.ets` 的「发现更多」区块：`WaterFlow().columnsTemplate('1fr 1fr').columnsGap().rowsGap()` + `LazyForEach(this.wfSource, ...)` + `FlowItem` 包 `WaterfallCard`；`.onScrollIndex` 提前预加载；保留骨架屏/空/错误重试/底部 LoadingFooter/没有更多了。`@State wfSource: WaterfallDataSource` 替代原 `wfList` 数组。
  - `WaterfallCard` 根 `width('100%')`（由列宽自适应，去掉固定 cardWidth）。
- 关键 SDK 26 差异（实测踩坑）：`WaterFlow` 列数只能链式 `.columnsTemplate('1fr 1fr')`；`IDataSource`/`DataChangeListener` 在该 SDK 的 `@kit.ArkUI` 及 `@ohos.arkui.adapter/data` 均未导出/找不到，用本地结构匹配绕过。详见 MEMORY.md 工程注意事项。
- lint：Recommend.ets / WaterfallDataSource.ets 0 ERROR（仅 router 弃用 HINT）。
- 注意：仍受本沙箱 LS 陈旧缓存影响（改 import 路径时曾报 2305/2307，最终用结构匹配解决后干净）。

## 瀑布流"发现更多"不显示修复
- **根因**：`Recommend.ets` 中 `wfLeft`/`wfRight` 用 **getter 属性**返回新数组，ArkTS `ForEach` 无法对每次重新创建的数组做正确 diff 追踪 → 数据加载后 UI 不刷新/不显示。
- **修复**：将 getter 删除，改为 `@State wfLeft` / `@State wfRight` 两个显式状态数组；新增 `splitWaterfallColumns()` 方法在每次 `wfList` 赋值后同步拆分奇偶到左右列；所有 4 处赋值点（首页成功/首页 fallback/catch fallback/下一页追加）均已加上调用。
- lint 验证：0 ERROR（仅 router 弃用 HINT）。
