## 1. 文档概述

### 1.1 项目背景

电商平台价格波动频繁，"先涨后降"的虚假促销套路普遍存在。消费者缺乏有效工具来追踪商品的历史价格、跨平台比价和识别真正的低价时机。市面上虽有慢慢买、什么值得买等应用，但大多依赖爬虫技术，存在法律风险，且用户数据安全性堪忧。

### 1.2 产品愿景

做一个合规、隐私友好的鸿蒙原生价格监控工具。用户在任何平台购物时，看一眼价格走势就知道该不该下手。

### 1.3 产品核心价值主张

| 价值维度 | 描述 |
|:---|:---|
| **省钱** | 历史价格追踪 + 降价提醒，帮助用户把握最佳购入时机 |
| **省心** | 自动监控，无需人工比价；多平台一键对比 |
| **安心** | 数据全本地存储，不上传云端，无需注册登录 |
| **透明** | 识别"先涨后降"假促销，揭露真实价格变化 |

### 1.4 适用范围

本文档定义 PriceHound **MVP 阶段（v1.0）至完整版（v3.0）** 的全部功能需求，作为产品设计、技术开发和测试验收的统一依据。

## 2. 产品定位与目标用户

### 2.1 产品定位

- **类型**: 工具类应用（Utility）
- **定位**: 面向个人消费者的电商价格监控与智能决策助手
- **差异化**: 纯鸿蒙原生、隐私优先（全本地）、合规数据获取（无爬虫）

### 2.2 目标用户画像

#### 核心用户 A：理性购物者

- 年龄 25-40 岁，有固定收入
- 购物前习惯多渠道比价，关注618/双11等大促
- 痛点：不知何时是最低价，担心买贵
- 动机：省钱、避开消费陷阱

#### 核心用户 B：数码产品爱好者

- 年龄 18-35 岁，男性居多
- 高频关注手机、电脑、耳机等数码产品
- 痛点：数码产品价格波动大，换代快，想抓最佳入手点
- 动机：在对的时间用对的价格买到对的产品

#### 扩展用户 C：家庭采购主力

- 年龄 30-50 岁，女性居多
- 定期采购日用品、家电等
- 痛点：品类多、频次高，难以逐一追踪
- 动机：批量管理、长期监控、节省家庭开支

### 2.3 用户场景

| 场景 | 描述 | 核心诉求 |
|:---|:---|:---|
| 大促前观望 | 用户看中某商品，想确认大促价格是否真划算 | 历史走势图、假促销识别 |
| 跨平台比价 | 同款商品淘宝、京东、拼多多都有，想找最低价 | 多平台比价、价格排名 |
| 等降价入手 | 用户不着急买，希望在降到目标价时收到通知 | 降价提醒、目标价格 |
| 购物复盘 | 想了解自己过去一段时间的购物省钱情况 | 省钱报告、数据看板 |
| 发现机会 | 不知道买什么，想看看最近哪些商品在降价 | 降价排行、智能推荐 |

## 3. 功能需求详解

> **优先级标注**: 🟢 P0（MVP 必做）| 🔵 P1（核心版）| 🟡 P2（增强版）

### 3.1 商品管理

#### 3.1.1 商品搜索与添加 🟢

**功能描述**: 用户通过商品链接、关键词搜索或扫码三种方式将商品加入监控列表，系统自动提取商品信息。

**交互流程**:

```
[首页] → 点击"+"添加按钮 → 选择添加方式
    ├── 📎 粘贴链接 → 自动解析 → 确认页 → 添加到监控列表
    ├── 🔍 关键词搜索 → 搜索结果列表 → 选择目标商品 → 确认页 → 添加
    └── 📷 扫码 → 识别条形码/二维码 → 确认页 → 添加
```

**详细规则**:

| 添加方式 | 输入 | 自动提取信息 | 异常处理 |
|:---|:---|:---|:---|
| 商品链接 | 淘宝/京东/拼多多 URL | 商品名称、主图、当前价格、平台来源 | 链接无法识别 → 提示"暂不支持该平台" |
| 关键词搜索 | 商品关键词 | 搜索结果列表（名称、价格、平台缩略图） | 无结果 → 提示"未找到相关商品，请尝试其他关键词" |
| 扫码 | 条形码/二维码 | EAN/UPC 码匹配商品信息 | 无法识别 → 提示"未识别到有效条码" |

**验收标准**:
- [ ] 粘贴有效链接后，3 秒内完成解析并展示商品信息预览
- [ ] 支持的平台：淘宝、京东、拼多多（MVP 阶段至少支持 2 个）
- [ ] 自动提取信息的准确率 ≥ 95%
- [ ] 扫码识别响应时间 < 2 秒

#### 3.1.2 商品分类与标签 🔵

**功能描述**: 用户可创建自定义分类和标签来组织监控商品。

**分类管理**:
- 系统预置分类：数码产品、家用电器、服装鞋帽、日常消耗品、食品饮料、其他
- 用户可新增、编辑、删除自定义分类
- 每个商品属于一个分类

**标签系统**:
- 系统预置标签：🏷 想买、👀 观望、📉 已降价、⭐ 收藏
- 用户可创建自定义标签（颜色选择器）
- 每个商品可添加多个标签
- 支持按标签筛选商品列表

**置顶功能**: 长按商品卡片 → "置顶"选项 → 商品固定显示在列表顶部，带 📌 标识

**验收标准**:
- [ ] 支持创建/编辑/删除分类和标签
- [ ] 标签筛选器能正确过滤商品列表
- [ ] 置顶商品始终在列表最前

#### 3.1.3 批量管理 🟡

**功能描述**: 支持批量导入/导出商品列表，以及批量操作。

**批量导入**:
- 支持 CSV 格式导入（模板：商品名称, 链接, 目标价格）
- 导入前预览，确认后批量添加
- 重复商品自动去重提示

**批量导出**:
- 导出格式：CSV
- 导出内容：商品名称、平台、当前价格、历史最低价、添加时间、标签
- 支持选择导出范围（全部 / 指定分类 / 指定标签）

**批量操作**:
- 进入"编辑模式"（长按或多选按钮）
- 支持：批量删除、批量暂停监控、批量修改分类、批量添加标签

**验收标准**:
- [ ] CSV 导入错误行有明确的行号和原因提示
- [ ] 批量操作有二次确认弹窗
- [ ] 导出文件可在 Excel / WPS 中正常打开

### 3.2 价格追踪与监控

#### 3.2.1 智能定时监控 🟢

**功能描述**: 后台自动按设定频率抓取商品最新价格，支持自定义频率和手动刷新。

**监控频率选项**:
| 频率 | 适用场景 | 建议 |
|:---|:---|:---|
| 每 1 小时 | 闪购、限时促销商品 | 高耗电，仅建议短期使用 |
| 每 6 小时 | 普通关注的商品 | MVP 默认频率 |
| 每天 1 次 | 长期跟踪的商品 | 推荐日常使用 |
| 每周 1 次 | 不急买的商品 | 最省资源 |

**监控状态可视**:
- 🟢 绿色圆点：监控中
- 🟡 黄色圆点：等待下次刷新
- 🔴 红色圆点：上次获取失败
- ⏸ 灰色暂停图标：已暂停

**手动刷新**:
- 单商品下拉刷新（商品详情页）
- 全局一键刷新（首页顶部按钮）
- 刷新时显示加载动画，完成后更新价格时间戳

**验收标准**:
- [ ] 后台任务运行期间不影响前台应用流畅度
- [ ] 1 小时频率下，24 小时电量消耗增量 ≤ 5%
- [ ] 价格获取失败时，自动标记异常状态，不丢失历史数据

#### 3.2.2 价格变动记录 🔵

**功能描述**: 完整记录每次价格变动，支持时间范围筛选和历史回顾。

**记录内容**:
```
每次变动记录包含：
├── 变动时间（精确到分钟）
├── 当前价格
├── 变动金额（+/- ¥XX.XX）
├── 变动幅度（+/- X.X%）
├── 变动趋势标识（📈上涨 / 📉下跌 / ➡持平）
└── 数据来源平台
```

**时间筛选**:
- 快捷筛选：今天、近 7 天、近 30 天、近 3 个月
- 自定义时间范围选择器
- 筛选后显示「共 X 次价格变动」

**验收标准**:
- [ ] 价格未变动时不产生冗余记录
- [ ] 时间筛选结果与实际数据一致
- [ ] 变动记录列表支持滚动加载（超过 50 条时分页）

### 3.3 多平台比价 🔵

**功能描述**: 同一商品自动抓取主流平台价格，直观对比各渠道当前价和历史最低价。

**比价维度**:

| 维度 | 说明 |
|:---|:---|
| 当前价格 | 各平台最新抓取价格 |
| 历史最低价 | 该平台该商品的历史最低价 |
| 价格优势 | 当前价与全网最低价的差距（¥ / %） |
| 推荐指数 | 综合价格 + 历史低价 + 价格走势的推荐度（⭐1-5） |

**比价卡片布局**（每个平台一行）:
```
┌────────────────────────────────────────┐
│ 🛒 京东          ¥3,299    历史最低 ¥2,899 │
│ 当前价格位于历史中位，较上次下降 5.2%       │
│ [去购买] [查看走势]        推荐指数 ⭐⭐⭐⭐ │
├────────────────────────────────────────┤
│ 🛒 淘宝          ¥3,199    历史最低 ¥2,799 │
│ 当前价格位于历史低位                       │
│ [去购买] [查看走势]        推荐指数 ⭐⭐⭐⭐⭐ │
└────────────────────────────────────────┘
```

**验收标准**:
- [ ] 至少支持 2 个平台比价（MVP），完整版支持 3+
- [ ] 比价数据更新时间与最近一次抓取时间一致
- [ ] 「去购买」按钮可跳转至对应平台商品页

### 3.4 数据分析与可视化

#### 3.4.1 价格走势图 🟢

**功能描述**: 以 Canvas 绘制的折线图展示商品价格历史趋势，支持多时间维度和交互操作。

**时间维度切换**:
- Tab 切换：1周 / 1月 / 3月 / 6月 / 1年 / 全部
- 切换时图表平滑过渡动画

**图表元素**:
```
   价格(¥)
    │                              ● ← 当前价格（高亮圆点）
    │     ╱╲        ╱╲
    │    ╱  ╲      ╱  ╲    ╱╲
    │   ╱    ╲    ╱    ╲  ╱  ╲
    │  ╱      ╲  ╱      ╲╱    ╲___
    │ ╱        ╲╱                  ╲___
    │╱                                   ╲___
    └────────────────────────────────────────→ 时间
         ▲ 历史最高点    ▼ 历史最低点（标注）
```

**图表交互**:
- 双指缩放：放大/缩小时间范围
- 单指拖动：平移查看不同时间段
- 长按：显示该时间点的精确价格和日期浮层
- 双击：重置到默认视图

**验收标准**:
- [ ] 折线图数据点 ≥ 5 个时正常渲染
- [ ] 缩放/拖动响应延迟 < 100ms
- [ ] 历史最高/最低点标注位置准确，不与折线重叠
- [ ] 无数据时显示空状态插画 + "暂无价格数据，开始监控后自动记录"

#### 3.4.2 历史低价识别 🔵

**功能描述**: 自动计算并展示商品的历史低价、平均价、中位数等统计指标。

**统计面板**:
| 指标 | 说明 |
|:---|:---|
| 历史最低价 | ¥X,XXX（出现于 YYYY-MM-DD） |
| 历史最高价 | ¥X,XXX（出现于 YYYY-MM-DD） |
| 当前价格 | ¥X,XXX |
| 30 天平均价 | ¥X,XXX |
| 中位数价格 | ¥X,XXX |
| 当前处历史水位 | 「位于历史低位（前 10%）」/「位于历史高位（前 80%）」 |

**假促销识别**:
- 检测规则：促销前 7-30 天价格明显上涨（涨幅 ≥ 10%），促销时降回或接近原价
- 检测到假促销时，在商品详情页展示警告标识：⚠️ 「检测到疑似"先涨后降"行为，促销前 15 天涨价 20%」
- 假促销标记仅在数据充足时触发（至少 30 天历史数据）

**验收标准**:
- [ ] 统计指标计算与原始数据一致（抽样验证）
- [ ] 假促销识别准确率 ≥ 80%（需实际数据验证）
- [ ] 数据不足 30 天时，假促销检测标记为"数据不足，无法判断"

#### 3.4.3 价格预测 🟡

**功能描述**: 基于历史价格数据，使用移动平均法预测近期价格趋势，并给出购买建议。

**预测算法**（MVP 阶段）:
- 简单移动平均（SMA）：近 7 天 / 30 天价格移动平均线
- 趋势判断：SMA 斜率方向和幅度
- 不做精确价格预测，只做趋势方向判断

**购买建议文案**:
| 水位判断 | 建议 |
|:---|:---|
| 当前 ≤ 历史最低 × 1.05 | 🟢 「当前价格接近历史低位，建议入手」 |
| 历史最低 × 1.05 < 当前 ≤ 平均 × 0.9 | 🟡 「价格处于中等水平，可以观望」 |
| 当前 > 平均 × 0.9 | 🔴 「当前价格偏高，建议等待降价」 |
| 数据不足 | ⚪ 「数据积累中，持续监控后提供建议」 |

**验收标准**:
- [ ] 购买建议与统计指标逻辑一致
- [ ] 建议明确标注"仅供参考，不构成投资建议"
- [ ] 数据不足时不给误导性建议

### 3.5 降价提醒与通知

#### 3.5.1 智能降价提醒 🔵

**功能描述**: 用户可设置降价触发条件，满足时自动发送本地通知。

**提醒类型**:

| 类型 | 设置方式 | 示例 |
|:---|:---|:---|
| 目标价格提醒 | 输入期望价格 | "低于 ¥2,500 时提醒我" |
| 降幅提醒 | 输入降幅百分比 | "再降 10% 时提醒我" |
| 低于历史最低提醒 | 开关选项 | "低于历史最低价 ¥2,799 时提醒我" |

**设置交互**: 商品详情页 → 点击"设置提醒" → 弹出设置面板 → 选择提醒类型 → 输入阈值 → 保存

**提醒触发逻辑**:
- 每次价格抓取完成后，对比所有活跃提醒规则
- 满足条件 → 立即发送通知
- 同一规则 24 小时内最多触发 1 次（防骚扰）
- 价格反弹后再次下跌到阈值 → 再次触发

**验收标准**:
- [ ] 价格降至目标价时，5 分钟内发送通知
- [ ] 价格未达阈值时不会误触发
- [ ] 已触发过的规则不会在 24 小时内重复通知

#### 3.5.2 多种通知方式 🔵

**本地推送通知**:
- 使用 `@ohos.notification` 系统通知 API
- 通知内容模板：「PriceHound 降价提醒」+ 商品名称 + 当前价格 + 降价金额
- 点击通知 → 跳转到对应商品详情页

**每日/每周汇总报告**:
- 每日报告：当天有价格变动的商品汇总
- 每周报告：本周降价 Top 5 + 总节省金额统计
- 报告以通知形式推送，点击查看详情
- 用户可在设置中配置推送时间（默认每日 20:00）

**验收标准**:
- [ ] 通知在系统通知栏正确显示
- [ ] 点击通知能正确跳转到指定页面
- [ ] 汇总报告内容与数据看板统计一致

#### 3.5.3 通知管理 🔵

**功能**:
- 按商品单独开关提醒（商品列表右滑 → 关闭提醒）
- 通知历史记录页面：按时间倒序展示所有已发送通知
- 免打扰时段设置：全局静默时段（如 23:00-07:00）

**验收标准**:
- [ ] 关闭某商品提醒后，该商品价格变动不再触发通知
- [ ] 免打扰时段内的提醒在时段结束后不补发

### 3.6 数据看板与统计

#### 3.6.1 总览看板 🔵

## 6. UI/UX 设计规范

> 本节内容基于 `docs/DESIGN.md` 中的 Claude (Anthropic) 暖色调设计系统。PriceHound 的 UI 将严格遵循此设计语言，打造温暖、专业、可信赖的视觉体验。

### 6.1 设计哲学

PriceHound 的界面语言不是冰冷的工具面板，而更像一本精心排版的杂志，温暖、从容、有书卷气。整体建立在羊皮纸色调（`#f5f4ed`）的画布上，刻意唤起纸质阅读的触感而非数字屏幕的距离感。陶土色（`#c96442`）作为品牌主色，温暖、朴实，刻意回避科技产品常见的冷色系。

- **无衬线体用于功能表达**：按钮、标签、导航、表单等 UI 元素使用 Sans
- **宽行距阅读体验**：正文行高 1.60，接近纸质书自然阅读节奏
- **紧凑但有呼吸的标题**：标题行高 1.10-1.20，紧但不拥挤

- **空状态**: 极简线稿风插画，暖色调，概念性而非写实

### 6.8 设计约束（Do's & Don'ts）

**必须遵守**:
- ✅ 使用 `#f5f4ed` 作为页面主背景色。羊皮纸暖调是 PriceHound 的品牌基础
- ✅ 所有标题使用 Serif 字重 500，不高于此值
- ✅ 陶土色 `#c96442` 仅用于最高优先级的 CTA 和品牌时刻
- ✅ 所有中性色保持暖色调，每个灰色都带黄棕底调
- ✅ 使用环形阴影 `0px 0px 0px 1px` 而非传统投影
- ✅ 卡片圆角使用 8-16vp
- ✅ 正文行高保持 1.60
- ✅ 升降价格使用语义色区分：降价陶土色，涨价暖红色

**严格禁止**:
- ❌ 禁止使用冷色调灰色（如 #888、#999、#aaa）。色板内所有灰色都是暖调的
- ❌ 禁止 Serif 标题使用 Bold（700+）。字重 500 是上限
- ❌ 禁止引入陶土色和暖红色之外的饱和色。色板刻意保持克制
- ❌ 禁止使用直角或小圆角（< 6vp）
- ❌ 禁止使用重投影阴影
- ❌ 禁止使用 `#ffffff` 作为页面背景。永远用 `#f5f4ed` 或 `#faf9f5`
- ❌ 禁止将等宽字体用于非代码内容。Anthropic Mono 仅用于价格数字

### 7.3 数据流设计

```
┌──────────────┐    @State/@Link    ┌──────────────┐
│  ArkUI 组件  │ ◄─────────────────► │  ViewModel   │
│  (Pages/    │                     │  (@Observed) │
│   Components)│                     │              │
└──────────────┘                     └──────┬───────┘
                                            │
                                    ┌───────▼───────┐
                                    │  Repository   │
                                    │  (数据仓库)    │
                                    └──┬─────────┬──┘
                                       │         │
                              ┌────────▼──┐  ┌──▼──────────┐
                              │  SQLite   │  │  Network    │
                              │  (本地)   │  │  (远程API)  │
                              └───────────┘  └─────────────┘
```

**数据流规则**:
1. UI 组件通过 `@State`/`@Link` 绑定 ViewModel
2. ViewModel 不直接访问 SQLite 或网络，通过 Repository 层
3. Repository 封装数据访问逻辑，统一管理缓存与持久化
4. 网络请求结果先经 DataNormalizer 标准化再存入 SQLite
5. 数据变更通过 `@Observed` 自动触发 UI 更新

### 7.4 多源 Fallback 策略

```
PriceFetchService.fetchPrice(productId)
    │
    ├── 1. 尝试官方 API (优先级高)
    │   ├── 成功 → DataNormalizer.normalize() → 存入 SQLite → 返回
    │   └── 失败/超时(5s) →
    │
    ├── 2. 尝试第三方 API (fallback)
    │   ├── 成功 → DataNormalizer.normalize() → 存入 SQLite → 返回
    │   └── 失败/超时(5s) →
    │
    └── 3. 返回失败标记
        └── 保留上次价格记录，标记监控状态为"异常"
```

### 7.5 关键技术决策

| 决策点 | 选择 | 理由 |
|:---|:---|:---|
| 状态管理 | `@Observed` + `@State` | 鸿蒙原生方案，无需额外依赖 |
| 图表方案 | Canvas 自绘制 | 零依赖，完全控制样式匹配设计系统 |
| 数据库 | SQLite RDB | 鸿蒙原生关系型数据库，支持复杂查询 |
| 网络请求 | `@ohos.request` | 鸿蒙原生 HTTP 模块 |
| 后台任务 | `backgroundTaskManager` | 低功耗定时监控的唯一官方途径 |
| 图片缓存 | 内存 LRU + 磁盘缓存 | 减少重复下载，节省流量 |
| 路由方案 | 鸿蒙 Router API | 原生页面路由 |

## 10. 风险评估与应对

| 风险 | 影响 | 概率 | 应对策略 |
|:---|:---|:---|:---|
| **数据源不稳定** | 价格数据中断，影响所有功能 | 高 | 多源 fallback 架构；缓存上次有效数据；异常状态友好提示 |
| **官方 API 申请困难** | 初期只能依赖第三方数据 | 高 | MVP 先用第三方 API；逐步申请官方 API；保持数据标准化层与数据源解耦 |
| **鸿蒙后台任务限制** | 定时监控频率受限，无法高频刷新 | 中 | 设置合理频率（1h 起步）；在应用前台时执行积压任务；文档说明限制 |
| **第三方 API 成本** | 免费额度用完后产生费用 | 中 | 控制默认监控频率；按商品数限制免费用户；探索免费公开数据源 |
| **鸿蒙生态不成熟** | 某些 API 不稳定或有 Bug | 中 | 核心逻辑保持与平台 API 解耦；关注 HarmonyOS 版本更新；预留降级方案 |
| **价格预测准确度不足** | 用户信任度下降 | 低 | 仅做趋势建议不作精确预测；明确标注"仅供参考"；低数据量时不给建议 |
| **Canvas 性能不足** | 大量数据点时图表卡顿 | 低 | 数据采样降频（>200 点自动聚合）；虚拟化渲染；分页加载 |
| **合规风险** | 使用爬虫导致法律问题 | 低 | **坚决不使用爬虫**，仅使用官方 API 和授权第三方服务 |
