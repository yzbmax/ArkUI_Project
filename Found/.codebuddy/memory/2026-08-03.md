## PriceHound 项目 ArkTS 严格模式编译报错修复（独立工程，非 Found）

- 用户 `PriceHound` 工程（加密货币比价 App，`d:/HarMonyProjectPath/PriceHound`）PreviewArkTS 构建失败，报错均为 ArkTS 严格规则 `arkts-no-*`。
- 修复 4 个文件：
  - `service/CoinGeckoApi.ets:59` — 内联对象字面量作类型 `as { prices: ... }` → 新增 `interface MarketChartResult` 显式声明。
  - `utils/PriceUtil.ets:22` — 数组解构 `const [intPart, decPart] = v.split('.')` → 改为 `parts[0]`/`parts[1]`（arkts-no-destruct-decls）。
  - `utils/DateUtil.ets` — 静态方法内 `this.pad(...)`/`this.formatDate(...)`/`this.formatTime(...)` → 改 `DateUtil.xxx`（arkts-no-standalone-this）。
  - `utils/RouterUtil.ets` — 静态方法内 `this.push(...)` → `RouterUtil.push(...)`；内联对象字面量 `{ productId: ... }` 传参 → 新增 `interface ProductDetailParams`/`AlertSettingParams` 显式类型（arkts-no-standalone-this + arkts-no-untyped-obj-literals）。
- 注意：`router.pushUrl({ url, params })` 是框架 `RouterOptions` 类型参数，非违规；未改。
- 该工程与当前 Found 工作区独立，是另一个未跟踪的 HarmonyOS 项目。
- 第二轮修复（同一工程）：`RouterUtil.ets` 将显式接口 `ProductDetailParams`/`AlertSettingParams` 传给 `push(params: Record<string, Object>)` 时报 `Index signature for type 'string' is missing`。原因：ArkTS 接口无字符串索引签名时不满足 `Record<string, Object>` 可赋值性。修复：把 `push`/`replace` 的 `params` 形参类型由 `Record<string, Object>` 改为 `Object`（与 `router.pushUrl` 的 `RouterOptions.params?: Object` 一致），并去掉接口上曾加的 `[key: string]: Object` 索引签名（避免 string 不兼容 Object 的新错）。显式接口实例可赋给 `Object`，同时满足 `arkts-no-untyped-obj-literals`。
- 经验：ArkTS 中 `Record<string, Object>` 要求调用方提供带索引签名的类型；若想传任意自定义接口，最好把目标形参声明为 `Object`（或 `ESObject`），而非 `Record<string, Object>`。
- 第三轮修复（同一工程，最终方案）：上轮把 `params` 改为 `Object` 后，`router.pushUrl({ url, params })` 内联字面量因失去 `RouterOptions` 精确匹配又报 `arkts-no-untyped-obj-literals`（行 15/23）。最终方案：① `push`/`replace` 形参恢复为 `Record<string, Object>`（让内联字面量重新匹配 `RouterOptions`）；② 参数接口改为带 `[key: string]: Object` 索引签名且属性类型声明为 `Object`（如 `productId: Object`），这样既满足 `Record` 可赋值性，又避免 `string` 不兼容 `Object` 的索引签名报错。构造处 `string` 值赋给 `Object` 字段在 ArkTS 合法。
- 结论：ArkTS 路由参数封装的稳妥写法是形参用 `Record<string, Object>`，自定义参数接口必须带 `[key: string]: Object` 索引签名（属性类型用 `Object`）。
- 第四轮修复（同一工程）：ArkTS **不支持索引签名**（`arkts-no-indexed-signatures`），故第三轮的 `[key: string]: Object` 方案也失败。最终方案：① 参数接口恢复为普通属性（`productId: string` 等），不加索引签名；② `push`/`replace` 形参用 `Object`（可接受任意显式接口实例，满足 arkts）；③ 内部不再直接内联 `{ url, params }` 传给 `router.pushUrl`（会因 params 是 Object 宽类型失配 `RouterOptions` 而报 arkts-no-untyped-obj-literals），而是显式声明 `const opt: RouterOptions = { url: route, params: params };` 再传入。`RouterOptions` 是 ArkUI 全局类型，配合 `import { router } from '@kit.ArkUI'` 可用。
- 关键经验：ArkTS 严格模式三大雷区——(a) 静态方法禁用 `this`；(b) 禁用解构/内联对象字面量作类型/未类型化对象字面量；(c) **不支持索引签名 `[key: string]: ...`**，因此自定义类型无法赋值给 `Record<string, Object>`，需改用 `Object` 形参 + 显式 `RouterOptions` 注解规避内联字面量 untyped 报错。
- 第五轮修复（查阅华为官方文档后）：`RouterOptions` **并非全局可用名**（编译器提示 `Did you mean 'RotateOptions'?`），故 `const opt: RouterOptions` 报 `Cannot find name`。华为官方示例写法为 `router.pushUrl({ url: 'B', params: {...} as Type })`，核心是**每个对象字面量必须显式标注类型或 `as Type` 断言**（`arkts-no-untyped-obj-literals`）。最终方案：在 `RouterUtil.ets` 自定义 `interface RouteOptions { url: string; params?: Object }`，`push`/`replace` 内部用 `const opt: RouteOptions = { url: route, params: params }; router.pushUrl(opt);`。`RouteOptions` 与框架 `RouterOptions` 结构兼容（url:string, params?:Object），框架接受；同时规避了 `RouterOptions` 全局名不可用与 untyped-obj-literals 两类报错。
- 已确认 `PriceHound` 工程中除 `RouterUtil` 外无其他裸 `router.pushUrl({...})` 调用（均已收敛到 `RouterUtil.push/replace`）。
- 第六轮修复（查阅华为生态文档+掘金官方示例）：上一轮自定义 `RouteOptions` 仍报错，因为自定义 interface 实例传给期望 `RouterOptions` 的参数时被当作匿名对象失配，触发 untyped-obj-literals。**正确写法**：`RouterOptions` 是 `router` 命名空间下的类型，用 `router.RouterOptions` 访问（不需单独 import）。改为 `const opt: router.RouterOptions = { url: route, params: params }; router.pushUrl(opt);`。`params: Object` 与 `RouterOptions.params?: Object` 兼容。这是华为官方推荐写法（`const options: router.RouterOptions = {...}; router.pushUrl(options);`）。
- 结论：`RouterUtil` 路由封装最终形态 = `params: Object` 形参 + `const opt: router.RouterOptions = { url, params }; router.pushUrl(opt);`。
- 第七轮（8/4）：上一轮 `router.RouterOptions` 仍报 untyped-obj-literals（行15/24），说明该 SDK 版本 `router.RouterOptions` 对编译器不可见/不可用，且自定义 interface 中间变量破坏上下文推断被当匿名对象。最终正确写法（华为官方示例 `router.pushUrl({ url, params: {...} as Type }` 的等价）：**直接把字面量传给 `router.pushUrl`，不定义中间变量、不用自定义类型标注**，靠函数参数类型提供上下文推断；内层 `params` 用 `as Record<string, Object>` 显式断言（`params: Object` 形参 → `params as Record<string, Object>`）。即 `router.pushUrl({ url: route, params: params as Record<string, Object> })`。外层靠上下文推断、内层显式标注，双双满足 arkts-no-untyped-obj-literals。
- 关键经验提炼：ArkTS 严格模式下给 `router.pushUrl` 传参的**唯一稳妥模式** = 直接字面量 + 内层 `as Record<string, Object>`，不要中间 `const opt` 变量（会破坏上下文推断）。`RouterOptions` 全局名及 `router.RouterOptions` 在部分 SDK 不可用，不可依赖。
