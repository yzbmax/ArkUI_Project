## 修复：Outline SVG 图标背景被 fillColor 填充问题

### 根因
所有 52 个 SVG 图标是 Tabler Icons outline 风格，`<svg>` 标签设置了 `fill="none" stroke="currentColor"`，但子级 `<path>` 绘图元素没有**显式**设置 `fill="none"`，仅依赖从父级继承。HarmonyOS 的 SVG 渲染器不能正确继承该属性，导致 `Image.fillColor()` 把图标的透明背景也一并填充颜色，outline 图标变成实心色块。

### 修复
Python 脚本批量处理所有 52 个 SVG 文件：
1. `stroke="currentColor"` → `stroke="#000000"`（HarmonyOS 无 CSS currentColor 上下文）
2. 所有绘图 `<path>` 元素显式添加 `fill="none"`（跳过已含 `fill="none"` 的边界框路径 `M0 0h24v24H0z`）

修复后 `fillColor()` 只会作用于 `stroke="#000000"` 的线条像素，透明区域保持透明。

## 迁移：Image.fillColor() → Shape + Path Icon 组件（根治 outline 填充问题）

### 最终根因
上一轮的 SVG 修改（显式 `fill="none"` + `stroke="#000000"`）在用户环境中**仍然无效**——`Image.fillColor()` 在当前 HarmonyOS 环境里会把闭合 outline 路径（播放三角形、暂停双条、跳过箭头等）中间也填实，SVG 的 `fill="none"` `stroke="currentColor"` 机制未被尊重。

### 修复方案
放弃 `Image.fillColor`，改用 inline `Shape` + `Path` 渲染，显式 `.fill('#00000000')`（透明填充）+ `.stroke(fg)` 着色，从机制上保证中间不被填充：

## 修复：@Prop size 与内置属性冲突导致编译失败
- 错误：`Property 'size' in type 'Icon' is not assignable to the same property in base type 'CustomComponent'`
- 根因：`size` 是 ArkUI `CustomComponent` 的内置属性（类型为 `(value: SizeOptions) => CommonAttribute`），不能用 `@Prop size` 覆盖
- 修复：`@Prop size` → `@Prop iconSize`，全项目 `size:` → `iconSize:`（2 定义文件 + 22 调用文件）
- 涉及：Icon.ets, UI.ets(AvatarPlaceholder), 及所有 Icon()/AvatarPlaceholder() 调用点

## 修复：Icon 组件尺寸失控 + 图标/文本未垂直对齐
- 现象：顶部快捷入口图标极小；帖子卡片首图区域出现巨大黑色色块；多处 Icon+Text 行未垂直居中。
- 根因1：`Shape` 组件会随父布局拉伸/压缩，仅靠 `.width/.height` 无法保证实际渲染尺寸；需用固定尺寸容器 + `.flexShrink(0)` 约束。
- 根因2：`MockRepo` 示例图片使用了 outline SVG 图标（`photo/cup/book`），`Image` 组件将其拉伸后形成黑色实心块。
- 修复：
  - `Icon.ets`：用 `Stack({ alignContent: Alignment.Center })` 包裹 `Shape`，Stack 与 Shape 同时固定 `width/height = iconSize`，并加 `.flexShrink(0)`。
  - `MockRepo.ets` / `PublishLost.ets` / `PublishFound.ets`：示例图改用 PNG（`background/foreground/startIcon`）。
  - `HomeContent.ets`：快捷入口图标 `28` → `32`，并给 Column 加 `.alignItems(HorizontalAlign.Center)` 水平居中。
  - 全项目所有含 `Icon` / `AvatarPlaceholder` 的 `Row` 统一加 `.alignItems(VerticalAlign.Center)`（PostCard、MainTab、Settings、SearchPage、Login、Register、PublishLost/Found、FeedContent、EditProfile、Credit、Chat、ProfileContent、Admin、Match、MyPosts、MyClaims、MessageContent、Category、PostDetail）。
- 未新增 lint ERROR；预存 ERROR（PublishLost/PublishFound/EditProfile 的 Flex `space` 类型、FeedContent `$$this`）与本次改动无关。
