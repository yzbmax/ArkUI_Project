# Found 校园失物招领 App —— 演示项目流程

> 适用场景：课程答辩 / 项目汇报 / 验收演示。
> 全流程约 **12–15 分钟**，核心展示三条闭环：**发布→审核→曝光**、**认领→交付→完结**、**互动→通知→信用**。

---

## 一、项目一句话简介

**Found** 是一款 HarmonyOS 校园失物招领 App，采用 **ArkTS/ArkUI 前端 + Node.js(Express) 后端 + MySQL 数据库** 的三层架构。用户在 App 内发布失物/寻物，管理员审核后公开展示，失主与拾主通过**认领、线索、私信、智能匹配**完成物品归还，全程有**信用积分、消息通知**激励与反馈。

**架构图：**
```
ArkTS 页面（@kit.NetworkKit HTTP）
        │  BASE_URL: http://10.0.2.2:3000（模拟器） / PC局域网IP（真机）
        ▼
Express REST API（server/，端口 3000，{code,message,data} 信封，JWT 鉴权）
        ▼
MySQL 8.0（库 harmony，11 张表：user/post/comment/like/collect/claim/clue/
            message/credit_log/report/category）
```

## 四、详细演示脚本

### 场景 1：启动与登录（0:30）
- 打开 App → 开屏页 Splash → 进入登录页。
- 输入 `13800000002 / 123456` 登录 → 跳首页。
- **讲解点**：JWT token 持久化（Preferences），下次启动自动校验身份；密码 bcrypt 加密存储。

### 场景 2：首页信息流（2 分钟）
- 顶部**轮播图**（真实校园主题图，来自后端 static 静态资源，带主题色遮罩 + 标语）。
- 顶部 Tab：**最新 / 失物 / 寻物 / 附近**，切换即服务端过滤；上滑**加载更多**（服务端分页）。
- 点右上搜索 → 输入关键词（如"校园卡"）→ 空格分词 AND 检索；再看分类页图标分组。

### 场景 3：帖子详情与互动（1.5 分钟）
- 点进一条"进行中"帖子：
  - 图片轮播、状态徽标（进行中/已解决）、时间、紧急标记、浏览量。
  - **评论**：先发一条顶层评论 → 点另一条评论"回复"进入楼中楼 → 顶部出现"回复 @xxx ✕" → 提交后嵌套显示（**最多 2 层**）。
  - **点赞**、**收藏**（收藏后到"我的收藏"可见）。
- **讲解点**：`parent_id + reply_to_user_id` 实现评论嵌套；收藏进 `collect` 表。

### 场景 4：发布 → 审核 → 曝光（闭环一，1.5 分钟）
1. 小南点首页底部「+」→ **发布失物**：选分类、填标题/地点/描述、传图 → 提交 → Toast"提交成功，等待审核"。
2. 立即切回首页 → **这条新帖不在公开列表**（`audit_status=pending` 不对外）。
3. 退出登录 → 登录 `13800000001/admin123` 管理员 → 「管理后台 → 审核」→ 看到新帖（待审核）→ **通过**。
4. 退出 → 重新登录小南 → 回首页刷新 → **新帖已可见**（状态 processing）。
- **讲解点**：`post.status + audit_status` 双状态设计；未审核内容隔离，符合平台治理要求；发布即 +5 信用分。

### 场景 5：认领闭环（闭环二，2 分钟）
1. 换账号登录阿诚 `13800000003 / 123456`，进入刚才小南那**已通过审核**的帖子。
2. 阿诚点「提供线索」→ 填写线索 → 提交（线索进入 `clue` 表，`is_helpful` 待判定）。
3. 阿诚再点「申请认领」→ 填写认领表单 → 提交（认领进入 `claim` 表，状态 pending）。
4. 小南登录 → 「我的认领/线索」看到该帖的认领申请 → 点「认领审核」→ **通过**该认领。
5. 效果：帖子被置为**已解决（resolved）**并从公开列表消失；同帖其他 pending 认领自动驳回；触发系统通知。
- **讲解点**：认领闭环涉及 `claim` + `post` + `notif` 联动的事务性更新；防止一物多认领。

### 场景 6：智能匹配（1 分钟）
- 首页/「匹配」入口进入：演示一条同分类的「失物」与「寻物」被系统自动匹配提示。
- **讲解点**：同 `category` 下失物↔寻物双向匹配，命中进入消息中心"匹配"Tab。

### 场景 7：私信（1 分钟）
- 帖子详情点作者 →「发私信」→ 进入 Chat 会话 → 双方互发消息（实时刷新）。
- **讲解点**：会话对象带 `peerId` 定位发送对象；消息入 `message` 表。

### 场景 8：消息中心 + 信用积分（1 分钟）
- 底部 Tab「消息」：三个 Tab——**系统 / 互动 / 匹配**，均有真实未读角标；点进即标记已读。
  - 系统：审核结果、积分变动；互动：评论/认领/线索/点赞；匹配：同分类双向命中。
- 进「信用积分」页：余额、等级进度条（0/50/150/300/500 阶梯）、积分流水日志。
- **讲解点**：通知**不建独立大表**，从业务表实时派生 + `notif_read` 记录已读状态，避免数据冗余。

### 场景 9：个人中心沉淀（1 分钟）
- 「我的发布」：按状态（待审核/进行中/已解决）分组，可关闭帖子。
- 「我的认领/线索」：认领状态（待处理/已同意/已驳回）+ 线索有效判定。
- 「收藏与足迹」：收藏 Tab（后端 `collect` 表）+ 足迹 Tab（本地 Preferences 持久化浏览历史，可一键清空）。

### 场景 10：账号功能（1 分钟）
- 「编辑资料」：点头像 → 系统相册选图 → 预览 → 保存（base64 上传后端 → 覆盖 `user.avatar`）。
- 「找回密码」：输手机号 → 发送验证码（演示码 `123456`）→ 设新密码 → 用新密码登录成功。

### 场景 11：管理后台（1 分钟）
- 管理员 Tab：
  - **审核**：通过/驳回（可填驳回原因 `audit_remark`）。
  - **举报**：查看被举报帖子 → 处理（下架）。
  - **用户**：用户列表（角色/信用/状态）。
- **讲解点**：`requireAdmin` 中间件做权限隔离；全部接口参数化查询防 SQL 注入。

### 场景 12：收尾 + 问答（0:30）
- 总结三闭环（发布→审核→曝光 / 认领→交付→完结 / 互动→通知→信用）。
- 预留问答弹药：
  - **架构**：为何要后端中转？—— HarmonyOS 不能直连 MySQL，且需统一鉴权/审核/防注入。
  - **权限**：JWT + requireAuth / requireAdmin 两级；前端隐藏入口只是体验层，真正隔离在后端。
  - **图片**：DB 存相对路径 `/static/images/pN.png`，静态托管 + 前端拼 BASE_URL，换 host 不失效。
  - **通知**：派生式设计，读多写少场景用 `notif_read` 表记已读。

## 六、常见问题 FAQ

| 问题 | 处理 |
|---|---|
| 模拟器首页空白 / 网络失败 | 确认后端已 `npm start`；`BASE_URL` 必须 `http://10.0.2.2:3000`（模拟器回环映射）；cleartext 配置已内置 `network_config.json` |
| 真机连不上 | 真机改 PC 局域网 IP + 同网段 + 防火墙放行 3000 |
| 发布后首页看不到 | 属预期：需管理员审核通过才公开（演示点） |
| 认领通过后帖子消失 | 属预期：认领闭环把帖子置 resolved（演示点） |
| 忘记演示账号 | 见第二节表格 |
| 报错 `Column 'xxx' cannot be null` | 重跑 `npm run seed`（种子带最新表结构 ALTER 同步） |
